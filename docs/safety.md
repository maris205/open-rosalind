# Safety Notes

Open-Rosalind Edu 的核心安全原则是学习辅助、证据透明和人工核验。

## 内容安全边界

- 不提供临床诊断或治疗建议。
- 不伪造 DOI、PMID、实验数据、统计结果、样本量、作者或参考文献。
- 不声称生成内容已经经过实验验证。
- 不替代原始文献阅读、统计分析或导师审阅。
- 不鼓励学术不端。

## 工程权限建议

第一版作为 OpenHands Web GUI 中的 Edu Agent 使用时，建议仅面向开发者内测。若对学生开放，需要限制危险能力：

- 限制任意 shell command。
- 限制外部网络下载脚本。
- 限制读取宿主机敏感目录。
- 禁止自动 git push。
- 禁止自动发布内容。
- 禁止自动提交作业或论文。
- 禁止自动访问用户私人账号。

## Docker Python 沙箱

Agent 分支的开发版 Python 执行器只适合可信内测，默认要求用户逐次确认。当前安全边界包括：

- 禁止容器网络。
- 使用非 root 用户。
- 根文件系统只读。
- 移除 Linux capabilities 并启用 `no-new-privileges`。
- 限制 CPU、内存、进程数、临时磁盘和执行时间。
- 输入代码只读挂载，输出写入独立任务目录。
- 记录代码哈希、镜像、资源限制、日志、退出码和输出哈希。

公开部署前仍必须增加身份认证、速率限制、任务队列、用户级目录隔离、配额、文件清理策略和异常任务监控。Docker 守护进程不得暴露到公网，任务容器不得挂载 Docker socket 或宿主机敏感目录。

## 账户与会话

- 用户密码只保存 scrypt 哈希，不保存明文密码。
- 登录 Cookie 必须使用 HttpOnly 和 SameSite。
- 数据库只保存会话令牌的 SHA-256，不保存浏览器原始令牌。
- Docker 任务和输出文件必须绑定用户，下载时重新检查任务所有权。
- 数据库文件权限限制为仅服务账户可读写。
- 直接 HTTP 开发阶段不能启用 Secure Cookie；切换到 HTTPS 后必须启用 `ROSALIND_COOKIE_SECURE=1`。
- 当前没有邮箱验证、密码找回、管理员后台和多因素认证，不适合开放注册的正式生产环境。

## 项目记忆与自动任务

- 所有项目、记忆、计划和步骤必须检查用户所有权。
- 模型生成的计划必须先处于 draft，用户确认后才能执行。
- 每一步只执行当前指令，并继承受控的项目记忆和已完成步骤输出。
- 模型输出不得伪装成真实工具日志；Python 代码仍需单独人工确认后进入 Docker 沙箱。
- 步骤失败时停止连续执行，必须由用户重试。
- 服务重启时将遗留 running 步骤标记为失败，不自动假定其成功。
- 将步骤结果写入记忆时保留 task_step 来源标识。
- 只有 Worker 启动时可以恢复中断步骤；Web 重启不能修改 Worker 正在执行的状态。
- 同一计划使用 Redis 锁防止重复入队，锁必须在任务结束或 Worker 中断恢复时释放。

## 允许能力

- 读取用户上传的论文或文本。
- 解析 PDF。
- 生成 Markdown。
- 生成 DOCX。
- 调用受控文献搜索接口。
- 调用受控导出脚本。

## 输出要求

所有较长输出必须附带 Edu Mode disclaimer，并在生物医学 claim 处提醒用户人工核验。
