太棒了，这条路线可以直接开干。刚查了一下最新文档，**OpenHands 现在已经有 Agent Canvas 本地 Web GUI**，官方 quickstart 里说明 `agent-canvas` 可以启动完整本地栈，UI 默认在 `localhost:8000`；它也支持通过 `.openhands` 做 repository customization，并支持 Skills，Skills 可以作为 always-on context 或按需触发加载。([GitHub][1])

模型侧也没问题。OpenHands 的 LLM 设置支持 LiteLLM / OpenAI-compatible endpoint；阿里云 Model Studio / DashScope 的 Qwen 模型也提供 OpenAI-compatible 接口，所以可以先把 Qwen 当成 OpenAI-compatible provider 接进去。([OpenHands Docs][2])

下面这个可以直接丢给 Codex 作为设计方案和开发指令。

# Open-Rosalind Edu v0.1 设计方案

## 1. 项目目标

构建一个基于 OpenHands + Qwen + Open-Rosalind Edu Skills 的生物医学学习与学术写作 Agent。

产品定位：

> Open-Rosalind Edu 是面向生物医学学生、研究生和青年科研人员的 AI 文献学习与学术写作助手。

第一版目标不是做严肃可复现科研平台，而是做一个 Web-first 的轻量 Edu Agent，支持：

1. 文献精读
2. PDF 论文总结
3. 综述大纲生成
4. Introduction / Discussion 初稿
5. 中文/英文论文润色
6. 开题报告辅助
7. 作业/课程报告辅导
8. 引用与证据核验提醒
9. Markdown / DOCX 导出

重要边界：

* Edu Mode 不保证科研可复现性。
* 不提供临床诊断或治疗建议。
* 不伪造 DOI、PMID、实验数据、统计结果或参考文献。
* 所有输出默认为“学习与写作辅助草稿”，正式提交前必须人工核验。

## 2. 总体技术路线

采用：

```text
OpenHands Agent Canvas / Web GUI
    ↓
OpenHands Agent Runtime
    ↓
Qwen API / DashScope / OpenAI-compatible endpoint
    ↓
Open-Rosalind Edu Skills
    ↓
Biomedical writing / literature / education workflows
```

第一阶段优先复用 OpenHands，不重写 agent runtime。

核心原则：

1. 先跑通 Web 版。
2. 先接 Qwen 云端 API。
3. 先用 prompt-based skills，不急着做复杂工具。
4. 先限制危险执行权限。
5. 后续再改造成独立 Open-Rosalind Edu Web 产品。

## 6. `.openhands/AGENTS.md`

请创建文件：

```markdown
# Open-Rosalind Edu Agent

You are Open-Rosalind Edu, a biomedical learning and academic writing assistant.

Your role is to help biomedical students, graduate students, and early-career researchers understand literature, draft academic text, improve manuscripts, organize references, and prepare educational materials.

## Product Mode

You are running in Edu Mode.

Edu Mode is for:
- learning support
- literature reading
- academic writing assistance
- draft generation
- manuscript polishing
- thesis proposal preparation
- course report assistance
- biomedical concept explanation

Edu Mode is not:
- a clinical decision system
- a reproducible research execution engine
- a substitute for original literature verification
- a substitute for statistical analysis
- a tool for fabricating references or data

## Core Rules

1. Do not fabricate DOI, PMID, authors, journals, datasets, experimental results, p-values, sample sizes, or citations.
2. If evidence is missing, explicitly say that manual verification is required.
3. Clearly distinguish facts, user-provided information, and model-generated suggestions.
4. For biomedical claims, recommend checking original literature.
5. For medical or clinical topics, do not provide diagnosis or treatment advice.
6. For homework-like tasks, prefer tutoring, explanation, outline, and reasoning support over simply giving final answers.
7. Generated writing must be marked as draft text.
8. Never claim that generated text is experimentally validated.
9. If the user uploads a paper, summarize only what is available in the paper or clearly label inferred content.
10. At the end of substantial outputs, add the Edu Mode disclaimer.

## Default Output Style

Use Chinese by default unless the user asks for English.

Prefer structured outputs:
- title
- summary
- bullet points
- tables when useful
- draft sections
- verification checklist

## Default Disclaimer

提示：当前为 Open-Rosalind Edu 模式，输出仅用于学习、写作辅助和初稿生成，不保证结论、引用、实验方案或统计解释完全正确。正式提交、发表或用于科研决策前，请人工核验原始文献、数据和引用。本系统不提供临床诊断或治疗建议。
```

## 7. `paper_summary` Skill

创建：

```text
.openhands/skills/paper_summary/SKILL.md
```

内容：

```markdown
# Paper Summary Skill

Use this skill when the user uploads, pastes, or refers to a biomedical paper.

## Purpose

Help the user quickly understand a biomedical paper and convert it into structured study notes.

## Input

Possible inputs:
- PDF content
- paper title
- abstract
- DOI
- PMID
- copied paper text
- user question about the paper

## Output Structure

Return the answer in Chinese unless the user asks otherwise.

Use this structure:

1. 论文一句话总结
2. 研究背景
3. 核心科学问题
4. 研究对象 / 数据来源
5. 方法概述
6. 主要结果
7. 作者结论
8. 局限性
9. 可以用于写作引用的点
10. 需要人工核验的点

## Rules

- Do not invent results not present in the input.
- Do not invent PMID, DOI, authors, journal, or year.
- If the paper is incomplete, say which parts are missing.
- If the user asks for a critical review, include strengths and weaknesses.
- If the user asks for a Chinese summary, keep terminology accurate and natural.
- If the user asks for English output, write in academic English.
- Always include a manual verification checklist.
```

## 16. Qwen 接入建议

优先通过 OpenAI-compatible endpoint 接入。

需要环境变量：

```bash
export DASHSCOPE_API_KEY="your_api_key"
export QWEN_BASE_URL="https://dashscope.aliyuncs.com/compatible-mode/v1"
export QWEN_MODEL="qwen-plus"
```

在 OpenHands LLM advanced settings 中配置：

```text
Provider: OpenAI-compatible / Custom
Custom Model: openai/qwen-plus
Base URL: https://dashscope.aliyuncs.com/compatible-mode/v1
API Key: ${DASHSCOPE_API_KEY}
```

如果 OpenHands 当前版本更推荐 LiteLLM Proxy，则增加 LiteLLM proxy 配置：

```yaml
model_list:
  - model_name: qwen-plus
    litellm_params:
      model: dashscope/qwen-plus
      api_key: os.environ/DASHSCOPE_API_KEY
```

然后 OpenHands 里配置：

```text
Custom Model: litellm_proxy/qwen-plus
Base URL: http://localhost:4000
API Key: any-non-empty-key
```

## 17. 安全与权限限制

第一版作为 Edu Web，必须限制 OpenHands 默认工程 agent 的危险能力。

建议配置策略：

```text
禁用或限制：
- 任意 shell command
- 任意外部网络下载脚本
- 任意读取宿主机敏感目录
- 自动 git push
- 自动发布内容
- 自动提交作业/论文
- 自动访问用户私人账号

允许：
- 读取用户上传的论文
- 解析 PDF
- 生成 Markdown
- 生成 DOCX
- 调用受控文献搜索接口
- 调用受控导出脚本
```

如果短期无法精细禁用能力，则先仅限开发者内测，不对学生开放真实公网服务。

## 18. MVP 页面与入口

第一版直接使用 OpenHands Web GUI，但需要通过 README 和默认 prompt 引导用户。

后续独立前端需要四个入口：

```text
1. 文献精读
2. 综述写作
3. 论文润色
4. 开题/作业助手
```

每个入口对应一个预设 prompt。

### 文献精读入口 prompt

```text
请使用 Paper Summary Skill 帮我精读这篇生物医学论文。请输出：一句话总结、研究背景、核心问题、方法、主要结果、局限性、可引用点、需要人工核验的地方。
```

### 综述写作入口 prompt

```text
请使用 Literature Review Skill，围绕以下主题生成一个生物医学综述大纲，包括章节结构、每节写作要点、推荐检索关键词、潜在图表设计和需要核验的科学问题。
```

### 论文润色入口 prompt

```text
请使用 Manuscript Polish Skill 润色下面这段学术文本。要求保持科学含义不变，提高逻辑、清晰度和学术表达，并指出可能存在的科学表述风险。
```

### 开题报告入口 prompt

```text
请使用 Thesis Proposal Skill，围绕以下研究方向生成开题报告草稿，包括研究背景、科学问题、研究目标、研究内容、技术路线、创新点、可行性分析、预期结果和时间计划。
```
